# 唐诗村智能售货机系统运营操作手册

## 1. 适用范围

本手册面向日常业务运营人员，用于完成本系统后台与机器端的常见运营动作。

实施和技术支持人员负责服务器部署、现场网络、支付平台开户、密钥证书、机器本地凭据和故障日志采集等技术工作。

## 2. 使用前说明

- 后台页面名称以当前后台运营控制台为准。
- 机器端操作以机器本地运维入口为准。
- 本手册中的“补货”仅指机器端日常补货流程。后台“库存调整”只用于异常核对，不作为日常补货流程。
- 涉及新增或修改商品、机器、支付配置、库存等业务数据的走查，应在受控验收环境中完成。

### 2.1 登录后台

后台访问地址由部署或实施人员在服务部署完成后提供。

操作流程：

1. 打开已提供的后台访问地址。
2. 输入后台管理员用户名和密码。
3. 点击“登录”，进入管理后台。

登录后仅显示当前账号有权访问的功能。手册中的菜单未显示时，请联系后台管理员核对账号权限，不要借用其他人的账号。登录失败时，请检查用户名和密码；仍无法登录时，请联系后台管理员。

![后台登录](screenshots/admin-login.png)

### 2.2 退出后台

操作完成后，点击页面右上角的退出图标，返回登录页面。

## 3. 商品与规格管理

### 3.1 商品信息维护

适用场景：新增商品、修改商品名称、调整商品介绍、下架不再售卖的商品。

操作流程：

1. 进入后台商品管理页面。
2. 先按商品名称搜索，确认是否已存在同款商品。
3. 新增或编辑商品基础信息。
4. 检查商品展示名称是否便于顾客识别。
5. 保存后返回列表，确认状态与展示信息正确。

![商品管理页面](screenshots/admin-products-list.png)

![新增商品表单](screenshots/admin-product-create-drawer.png)

### 3.2 规格维护

适用场景：同一商品存在多个尺码、颜色或规格。

操作流程：

1. 进入目标商品详情。
2. 在规格区域新增或编辑规格项。
3. 保证顾客可区分的规格信息完整，例如颜色、尺码。
4. 停售规格应单独处理，不要误删仍在售的其他规格。

注意事项：

- 规格是库存绑定、价格销售和上架售卖的基础单位。
- 同款不同尺码应分别维护为不同规格。

![规格维护区域](screenshots/admin-product-sku-editor.png)

### 3.3 价格调整

适用场景：日常调价、活动结束恢复原价。

操作流程：

1. 进入商品或规格编辑页面。
2. 找到销售价格字段并修改。
3. 保存后回到列表或详情页复核新价格。
4. 如机器已在售，确认相关商品在机器端售价展示正常。

注意事项：

- 调价前先确认影响范围，避免误改同系列多个规格。
- 价格调整后，建议抽查对应机器的商品展示页。

![价格调整](screenshots/admin-product-price-edit.png)

## 4. 商品图与 Try-On Garment

### 4.1 商品图

商品图用于顾客浏览商品列表和商品详情时识别商品。

图片要求：

- 图片应直接展示售卖商品本体。
- 保持清晰、完整，避免严重裁切。
- 同一商品不同颜色可使用对应颜色图片。

操作流程：

1. 进入商品编辑页。
2. 上传或替换商品图。
3. 保存后检查列表与详情页是否能正确显示。

![商品图上传](screenshots/admin-product-image-upload.png)

### 4.2 Try-On Garment 来源

在商品列表的“新增试衣源”弹窗中，上传透明 PNG，填写可见颜色并选择 T 恤模板。

操作流程：

1. 上传并校验前视、单件、透明背景的 PNG；系统不会自动抠图或生成来源。
2. 核对预览和校验结果后创建草稿，并显式确认来源。
3. 显式激活 Try-On Garment。
4. 勾选同一商品下需要获得试衣资格的尺码规格，保存共享尺码关联。

![Try-On Garment 上传、确认、激活与关联](screenshots/admin-try-on-garment-upload.png)

## 5. 机器商品上架与补货

### 5.1 货道与商品绑定

适用场景：新机器上架、改货道、换商品。

操作流程：

1. 进入机器详情页。
2. 查看货道、库存或商品绑定区域。
3. 按货道位置确认当前绑定商品。
4. 调整绑定后复核销售状态与可售状态。

注意事项：

- 先确认货道位置，再确认商品，不要只看商品名称。
- 绑定调整后应同时复核售价和库存记录是否与现场一致。

![机器管理页面](screenshots/admin-machines-list.png)

![货道绑定商品规格](screenshots/admin-inventory-slot-binding.png)

### 5.2 机器端日常补货

机器端日常补货是记录现场实际补进商品数量的标准入口。

操作流程：

1. 在机器端进入本地运维入口。
2. 打开库存维护任务。
3. 进入日常补货或库存维护入口。
4. 按实际补入数量填写各货道新增件数。
5. 提交前检查补货后的预计库存。
6. 完成后返回库存维护列表，确认同步状态与可售状态恢复正常。

注意事项：

- 日常补货录入“新增数量”；最终盘点数量走库存盘点或异常纠偏流程。
- 现场发现后台库存与实物严重不一致时，先记录异常，再决定是否需要后台库存调整。
- 后台“库存调整”仅用于调查或纠偏，不叫补货。

![机器端库存维护入口](screenshots/machine-stock-refill-unavailable.png)

![机器端补货录入](screenshots/machine-stock-refill-confirmed.png)

## 6. 支付配置

### 6.1 支付宝商户配置

本节只说明如何在后台填写已准备好的支付宝商户信息，不说明商户申请、密钥生成或证书办理。

操作流程：

1. 进入支付配置页面。
2. 选择支付宝相关商户配置入口。
3. 按页面字段填写或上传已准备好的商户资料。
4. 保存后检查配置状态、密钥状态或回调状态是否正常。

注意事项：

- 商户配置与支付渠道启用是两个动作，不能混为一步。
- 若配置状态异常，应记录页面提示并转交实施或技术支持处理。

![支付管理页面](screenshots/admin-payments-tabs.png)

![支付宝配置表单](screenshots/admin-alipay-config-drawer.png)

### 6.2 支付渠道启用

操作流程：

1. 进入支付渠道管理页面。
2. 找到需要启用的渠道。
3. 按全局或机器范围启用渠道。
4. 保存后复核默认渠道、展示顺序和适用范围。

注意事项：

- 先确认商户配置已就绪，再启用渠道。
- 启用后应抽查目标机器是否出现预期支付方式。

![支付管理页面](screenshots/admin-payments-tabs.png)

![支付渠道启用](screenshots/admin-payment-channel-policy.png)

## 7. 机器认领与重领

### 7.1 首次认领

操作流程：

1. 在后台进入机器认领管理。
2. 为目标机器生成认领码。
3. 到机器端本地运维入口输入或完成认领。
4. 返回后台确认机器身份、位置和在线状态已关联到正确机器。

![机器管理页面](screenshots/admin-machines-list.png)

![机器认领码](screenshots/admin-machine-claim-code.png)

![机器端网络与认领](screenshots/machine-maintenance-commissioning.png)

### 7.2 重领

适用场景：机器重装、替换、现场恢复后重新绑定。

操作流程：

1. 在后台确认目标机器记录无误。
2. 使用后台的重领或重新认领入口生成新认领码。
3. 在机器端完成重领。
4. 复核机器是否仍归属于正确门店、位置和业务主体。

注意事项：

- 重领前先确认目标机器记录正确。
- 发现机器信息错绑时，先停手并保留页面证据。

![机器端重领码填写](screenshots/machine-reclaim-ready.png)

![机器端重领提交成功](screenshots/machine-reclaim-accepted.png)

## 8. 机器环境控制与基础操作

### 8.1 后台远程环境控制

适用场景：需要单次调整空调开关、目标温度或风阀/风速。

操作流程：

1. 进入机器详情页。
2. 找到环境控制区域。
3. 一次只发起一个控制动作。
4. 记录页面上的成功或失败反馈。

注意事项：

- 环境控制是一次性操作，不表示持续托管状态。
- 如需再次调整，应重新发起新的控制动作。

![机器管理页面](screenshots/admin-machines-list.png)

![机器环境控制](screenshots/admin-machine-environment-control.png)

注意事项：

- 本手册覆盖业务操作相关入口。系统级修复由实施或技术支持处理。
- 本地运维完成后，应返回顾客界面并确认机器可正常待机。

## 9. 订单、支付与出货异常查看

### 9.1 订单异常查看

操作流程：

1. 进入订单页面并搜索订单号、机器或时间范围。
2. 打开订单详情。
3. 核对订单状态、支付状态、出货状态和时间线。

记录内容：

- 订单号
- 机器名称或编号
- 异常发生时间
- 当前订单状态
- 是否已见到支付事件、退款动作或人工处理入口

![订单管理页面](screenshots/admin-orders-list.png)

![订单详情](screenshots/admin-order-detail.png)

### 9.2 支付异常查看

查看内容：

- 支付状态是否停留在处理中、失败或待人工处理
- 支付事件记录是否完整
- 是否存在退款、关闭、查询等安全操作入口

注意事项：

- 只使用后台已有的安全动作入口。
- 不直接修改数据库或支付状态。
- 页面缺少安全操作时，应记录为产品缺口，不用线下变通替代。

![支付管理页面](screenshots/admin-payments-tabs.png)

![支付异常处理入口](screenshots/admin-payment-incident-actions.png)

### 9.3 出货异常查看

查看内容：

- 出货状态
- 订单时间线
- 是否已有退款或人工处理记录
- 是否需要同步现场核实货道情况

注意事项：

- 先保留后台证据，再安排现场复核。
- 若订单、支付、出货信息彼此矛盾，应记录完整页面信息并升级处理。

## 10. 异常记录要求

遇到无法按手册完成的情况，请至少记录：

- 页面名称
- 操作前提
- 实际步骤
- 报错提示或异常状态
- 订单号、机器号、商品或规格
- 页面截图

缺少安全入口、页面契约错误、请求异常、流程无法闭环时，应作为产品问题跟踪，不写入正式操作手册作为常规操作步骤。
