# Vision Machine Protocol V2

VEM and `vending-vision` use the strict `vem.vision.v2` contract published by
`packages/shared/generated/vision-v2`. The generated bundle is the wire source
of truth; this document only records ownership and lifecycle invariants.

## Preserved core capabilities

Vision independently reports top-camera presence and departure, front-camera
profile, ambient light, ping/pong, camera-role maintenance, health, and
recorded-video or DirectShow source evidence. A contract or Fast capability
degradation never blocks ordinary sale readiness.

## Try-on attempt lifecycle

Machine starts one attempt with `vision.try_on.attempt.start`. The public phases
are `acquiring -> generating -> completed`; `failed` and `canceled` are terminal
outcomes, and `vision.try_on.attempt.accepted` is only an acknowledgement, not a
phase. There is no percentage or compatibility progress event in V2.

During `acquiring`, Vision owns the front camera and publishes an attempt-scoped
tokenized loopback HTTP MJPEG reference (`streamType: "mjpeg"`) together with
truthful `occupancy`, `guidance`, and `manualCaptureAllowed` facts. No-person and
multiple-person observations always block capture. Machine sends
`vision.try_on.attempt.capture` for manual acquisition or
`vision.try_on.attempt.cancel` with only `user`/`route_leave`; manual acquisition
bypasses stability waiting only, never occupancy or alignment protection.

Capture closes the preview and releases the front-camera lease before
`generating`. Generation reports only coarse stages (`preparing` or `rendering`)
and never a percentage. Vision owns the source frame; Machine never extracts
generation input from rendered preview bytes. One active nonterminal attempt is
allowed machine-wide. Replacement, disconnect, departure, timeout, route leave,
user cancellation, or other failure publishes exactly one terminal event, with
server cancellation reasons limited to `user`, `route_leave`, `disconnect`,
`departure`, `replaced`, and `timeout`. Attempt identity fences all late output.

Top-camera presence, departure, and ambient observation continue throughout the
flow. Profile signals do not redirect Machine while the try-on route is active,
and no `automaticFast` or AI fallback is part of this contract.

## Compatibility boundary

There is no dual-stack negotiation, fallback, legacy session lifecycle, or
legacy overlay preview surface. Machine and Vision exchange the V2 protocol and
bundle digest during hello/ready; mismatch withholds Vision business readiness
only.
